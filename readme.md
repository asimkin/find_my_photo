# Find My Photo — поиск фотографий по лицу

Скрипт находит все фотографии, на которых присутствует человек с опорного фото. Используется библиотека `face_recognition` (свёрточная нейросеть для распознавания лиц).

## Возможности

- Поиск по всей папке с фото (включая вложенные подпапки), поддержка форматов: `.jpg`, `.jpeg`, `.png`, `.gif`, `.bmp`.
- Регулируемая чувствительность поиска (tolerance).
- Результаты сортируются по убыванию уверенности совпадения.
- Топ-N совпадений копируются в отдельную папку (по умолчанию 100).
- Ускоренный режим: фото уменьшаются до 600px и используется модель `small` (примерно в 4 раза быстрее).
- Многопроцессная обработка: сканирование распараллеливается на несколько ядер (по умолчанию до 4 процессов).
- Дедупликация: одинаковые фотографии (копии) считаются один раз.
- Повторный запуск безопасен: папка с результатами `find_results/` исключается из поиска.
- Повреждённые или нечитаемые файлы пропускаются, а не прерывают поиск.
- Прогресс сканирования отображается в консоли (CLI) и в окне (GUI).
- Поиск по любой внешней папке (например, на Windows-диске в WSL: `/mnt/c/...`); путь можно задать флагом, интерактивно или полем ввода в GUI.
- Результаты можно сохранять в отдельную папку (`--output`) вместо папки с фото.
- Дедупликацию можно отключить (`--no-dedup`) для ускорения на медленных дисках.

## Установка

Требуется Python 3.9+ (на Linux для GUI дополнительно нужен системный пакет `python3-tk`).

```bash
./setup.sh        # Linux/macOS/WSL: системные пакеты + venv + все зависимости (нужен sudo один раз)
```

`setup.sh` выполняется один раз и автоматически вызывается при первом запуске `run_gui.sh`/`run_cli.sh`. Он:
1. Ставит недостающие системные пакеты Ubuntu/Debian: `python3-venv` (без него не создаётся venv), `python3-tk` (нужен GUI), `git` (для клонирования) — одним `sudo apt-get install`;
2. Создаёт виртуальное окружение `.venv/`;
3. Ставит зависимости из `requirements.txt` с флагом `--no-deps`, чтобы `face-recognition` не тянул старую версию моделей.

Вручную (Windows или без sudo):

```bash
python -m venv .venv
.venv/bin/pip install --no-deps -r requirements.txt     # Linux/macOS
.venv\Scripts\pip install --no-deps -r requirements.txt # Windows
```

> `dlib` ставится как готовый wheel — компиляция из исходников не нужна. Модели берутся из форка `face-recognition-models-ng` (поддержка современных setuptools, без устаревшего `pkg_resources`). `tkinter` — системный пакет, через pip на Linux он не ставится.

## Запуск на Windows через WSL

Проще всего использовать проект на Windows внутри WSL: GUI рисуется автоматически через WSLg, а фото с Windows-диска доступны по пути `/mnt/c/...`. Отдельная установка Python под Windows не нужна.

1. **Включить WSL.** В PowerShell от имени администратора:
   ```powershell
   wsl --install
   ```
   Перезагрузи компьютер.

2. **Установить Ubuntu** (из Microsoft Store или командой):
   ```powershell
   wsl --install -d Ubuntu
   ```
   При первом запуске Ubuntu создаст пользователя и пароль.

3. **Установить git** и склонировать проект:
   ```bash
   sudo apt update && sudo apt install -y git
   git clone https://github.com/asimkin/find_my_photo.git
   cd find_my_photo
   ```

4. **Запустить GUI**:
   ```bash
   ./run_gui.sh
   ```
   При первом запуске скрипт сам поставит `python3-venv`, `python3-tk` и зависимости (спросит пароль sudo), после чего откроется окно.

5. **Фото с Windows-диска** указывай как `/mnt/c/...`, например `/mnt/c/Users/<имя>/Pictures`. Папку с результатами тоже можно класть на Windows-диск, чтобы видеть её в проводнике.

> Окно работает через **WSLg** — оно появляется как обычное Windows-окно, настраивать `DISPLAY` не нужно. Если окно не открывается, проверь, что WSL обновлён: `wsl --update` (из PowerShell) и версия дистрибутива 2 (`wsl --set-version Ubuntu 2`).

## Запуск

### Через графический интерфейс

```bash
./run_gui.sh      # Linux/macOS/WSL
```

> Всегда запускай через `./run_gui.sh`, а не голым `python3` — иначе будут ошибки про `tkinter`/`face_recognition` (библиотеки живут в venv).

В окне нужно указать:
1. **Папку с фотографиями** — путь можно вставить текстом (например `/mnt/c/Users/simki/Pictures`) или выбрать кнопкой «Выбрать…».
2. **Опорное фото** — изображение, на котором хорошо видно лицо искомого человека. Путь тоже можно вставить или выбрать.
3. **Папку для результатов** *(необязательно)* — куда сохранять найденные фото. Пусто = `find_results/` в папке поиска; можно вставить путь или выбрать кнопкой.
4. **Чувствительность** — ползунок (меньше значение = строже поиск).

Последние папки, опорное фото и папка результатов запоминаются в `~/.config/find_my_photo/config.json` и подставляются при следующем запуске.

Недостающие зависимости скрипт попытается установить сам.

Результаты появятся в папке, указанной в пункте 3 (по умолчанию `find_results/` внутри выбранной папки). По завершении поиска в окне появляется кнопка **«Открыть папку с найденными фото»** и путь к результатам (по нему тоже можно кликнуть). На Windows папка дополнительно открывается автоматически.

### Через командную строку

```bash
./run_cli.sh [папка] [опции]
```

Примеры:

```bash
# поиск в папке по умолчанию (photos_to_search)
./run_cli.sh

# своя папка и своё опорное фото
./run_cli.sh /путь/к/фото -r /путь/к/опорному.jpg

# то же самое через флаг --photos
./run_cli.sh --photos /mnt/c/Users/simki/Pictures -r /путь/к/опорному.jpg

# строже, без параллелизма, сохранить топ-50
./run_cli.sh -t 0.5 -w 1 --top 50

# результаты в отдельную папку, без проверки копий (быстрее на /mnt)
./run_cli.sh /mnt/c/Users/simki/Pictures --output ./find_results --no-dedup
```

Если путь к папке не передан, CLI спросит его интерактивно (в скриптах без терминала сразу берётся `photos_to_search`).

Доступные опции:

| Флаг | По умолчанию | Описание |
|------|--------------|----------|
| `photos` | — | Папка с фотографиями (позиционный аргумент) |
| `-p, --photos` | — | То же, но флагом |
| `-r, --reference` | `my_reference_photo.jpg` | Опорное фото с лицом |
| `-t, --tolerance` | `0.6` | Чувствительность (меньше = строже) |
| `--top` | `100` | Сколько лучших совпадений сохранить |
| `-w, --workers` | авто | Кол-во процессов (1 = без параллелизма) |
| `-j, --jitters` | `3` | Точность энкодинга опорного фото (0–10) |
| `--max-side` | `600` | Макс. сторона фото при обработке, px |
| `--output` | внутри папки поиска | Куда сохранить результаты |
| `--no-dedup` | выкл. | Не проверять копии по md5 (быстрее на медленных дисках) |

## Результаты

Для каждой найденной фотографии выводится:
- **Confidence** — уверенность совпадения в процентах (чем выше, тем лучше).
- **Distance** — евклидово расстояние между векторами лиц (чем меньше, тем точнее).

По завершении создаётся папка `find_results/` (внутри папки поиска; её можно перенаправить флагом `--output`):

```
find_results/
├── results.txt       # лог поиска со статистикой и топ-100 совпадений
└── top_matches/      # копии лучших совпадений (001_..., 002_..., ...)
```

| `setup.sh` | Одноразовая настройка: tkinter + venv + зависимости |

## Архитектура

Проект построен по схеме **тонкие интерфейсы + общее ядро**: вся логика поиска находится в одном модуле, а GUI и CLI — лишь способы передать в него параметры и показать результат.

```
        ┌─────────────┐   ┌─────────────┐
        │ findmyphoto │   │ search_cli  │   ← интерфейсы (Tkinter / argparse)
        │    (GUI)    │   │    (CLI)    │
        └──────┬──────┘   └──────┬──────┘
               └────────┬────────┘
                        ▼
              ┌─────────────────┐
              │   search_core   │   ← ядро: вся логика поиска
              │  find_photos()  │
              └─────────────────┘
```

### `search_core.py` — ядро

Последовательность работы `find_photos()`:

1. **Загрузка опорного фото** — лицо(а) кодируются в 128-мерный вектор эмбеддинга (`model="small"`, `num_jitters` повышает точность за счёт повторных проходов).
2. **Сбор фотографий** — рекурсивный обход папки (`collect_photos`); папка `find_results/` исключается, чтобы повторные запуски не искали лицо среди своих же результатов.
3. **Дедупликация** — одинаковые файлы отсекаются по md5-хэшу.
4. **Сканирование** — каждое фото уменьшается до 600px и кодируется; расстояние до опорного лица считается через `face_recognition.face_distance` (евклидова метрика). Если оно меньше `tolerance` — фото попадает в результаты. Сканирование идёт либо в одном процессе, либо в пуле процессов (`ProcessPoolExecutor`, до 4 воркеров) с откатом на последовательный режим при ошибке.
5. **Сохранение** — результаты сортируются по возрастанию distance, пишется `results.txt` и копируются топ-N совпадений в `top_matches/`.

### Как связаны модули

- `findmyphoto.py` и `search_cli.py` импортируют `search_core` и вызывают единственную функцию `find_photos(photos, reference, tolerance, ...)`, получая на выходе dict со статистикой и списком совпадений.
- Прогресс передаётся из ядра наружу через callback `progress_callback(done, total, path)` — CLI обновляет `tqdm`, GUI — прогресс-бар.
- Благодаря единому ядру изменение логики (модель, tolerance, топ-N, форматы) делается в одном месте и сразу работает в обоих интерфейсах.

### Формат совпадения

Каждый результат — dict:

| Поле | Значение |
|------|----------|
| `path` | путь к фотографии |
| `distance` | евклидово расстояние до опорного лица (меньше = точнее) |
| `faces_count` | сколько лиц найдено на фото |
| `face_index` | индекс лучшего лица на фото |

### Ограничения

- Обработка CPU-bound: при отсутствии воркеров (`-w 1`) сканирование однопоточное и занимает несколько минут на 1000+ фото.
- Для скорости используется модель `small` и уменьшение до 600px — на сильно размытых или крошечных лицах точность ниже, чем у полной модели.
- Порог сравнения `tolerance=0.6` эмпирический: ниже — меньше ложных срабатываний, но можно пропустить реальные совпадения.
