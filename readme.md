# Find My Photo — поиск фотографий по лицу

Скрипт находит все фотографии, на которых присутствует человек с опорного фото. Используется библиотека `face_recognition` (свёрточная нейросеть для распознавания лиц).

## Возможности

- Поиск по всей папке с фото (включая вложенные подпапки), поддержка форматов: `.jpg`, `.jpeg`, `.png`, `.gif`, `.bmp`.
- Регулируемая чувствительность поиска (tolerance).
- Результаты сортируются по убыванию уверенности совпадения.
- Топ-N совпадений копируются в отдельную папку (по умолчанию 100).
- Ускоренный режим: фото уменьшаются до 600px и используется модель `small` (примерно в 4 раза быстрее).
- Многопроцессная обработка: сканирование распараллеливается на несколько ядер (по умолчанию до 4 процессов).
- Дедупликация: одинаковые фотографии (копии) считаются один раз.
- Повторный запуск безопасен: папка с результатами `find_results/` исключается из поиска.
- Повреждённые или нечитаемые файлы пропускаются, а не прерывают поиск.
- Прогресс сканирования отображается в консоли (CLI) и в окне (GUI).

## Установка

Требуется Python 3.8+.

```bash
pip install face-recognition pillow opencv-python tqdm numpy
```

> На Linux также могут понадобиться системные пакеты для `dlib`/`face_recognition` (например `build-essential cmake libboost-all-dev`). На Windows удобнее ставить через `pip install cmake` и официальный Visual Studio Build Tools.

## Запуск

### Через графический интерфейс

```bash
python findmyphoto.py
```

В окне нужно указать:
1. **Папку с фотографиями** — каталог, где лежат снимки для поиска.
2. **Опорное фото** — изображение, на котором хорошо видно лицо искомого человека.
3. **Чувствительность** — ползунок (меньше значение = строже поиск).

Недостающие зависимости скрипт попытается установить сам.

Результаты появятся в папке `find_results/` внутри выбранной папки.

### Через командную строку

```bash
python search_cli.py [папка] [опции]
```

Примеры:

```bash
# поиск в папке по умолчанию (photos_to_search)
python search_cli.py

# своя папка и своё опорное фото
python search_cli.py /путь/к/фото -r /путь/к/опорному.jpg

# строже, без параллелизма, сохранить топ-50
python search_cli.py -t 0.5 -w 1 --top 50
```

Доступные опции:

| Флаг | По умолчанию | Описание |
|------|--------------|----------|
| `photos` | `photos_to_search` | Папка с фотографиями |
| `-r, --reference` | `my_reference_photo.jpg` | Опорное фото с лицом |
| `-t, --tolerance` | `0.6` | Чувствительность (меньше = строже) |
| `--top` | `100` | Сколько лучших совпадений сохранить |
| `-w, --workers` | авто | Кол-во процессов (1 = без параллелизма) |
| `-j, --jitters` | `3` | Точность энкодинга опорного фото (0–10) |
| `--max-side` | `600` | Макс. сторона фото при обработке, px |

## Результаты

Для каждой найденной фотографии выводится:
- **Confidence** — уверенность совпадения в процентах (чем выше, тем лучше).
- **Distance** — евклидово расстояние между векторами лиц (чем меньше, тем точнее).

По завершении создаётся папка `find_results/`:

```
find_results/
├── results.txt       # лог поиска со статистикой и топ-100 совпадений
└── top_matches/      # копии лучших совпадений (001_..., 002_..., ...)
```

## Структура проекта

| Файл | Назначение |
|------|------------|
| `findmyphoto.py` | GUI-версия с окном Tkinter, прогресс-баром и автоустановкой зависимостей |
| `search_cli.py`  | Консольная версия с параметрами через `argparse` |
| `search_core.py` | Общая логика поиска (используется обоими интерфейсами) |
| `photos_to_search/` | Пример папки с фотографиями для поиска |
| `my_reference_photo.jpg` | Пример опорного фото |

## Архитектура

Проект построен по схеме **тонкие интерфейсы + общее ядро**: вся логика поиска находится в одном модуле, а GUI и CLI — лишь способы передать в него параметры и показать результат.

```
        ┌─────────────┐   ┌─────────────┐
        │ findmyphoto │   │ search_cli  │   ← интерфейсы (Tkinter / argparse)
        │    (GUI)    │   │    (CLI)    │
        └──────┬──────┘   └──────┬──────┘
               └────────┬────────┘
                        ▼
              ┌─────────────────┐
              │   search_core   │   ← ядро: вся логика поиска
              │  find_photos()  │
              └─────────────────┘
```

### `search_core.py` — ядро

Последовательность работы `find_photos()`:

1. **Загрузка опорного фото** — лицо(а) кодируются в 128-мерный вектор эмбеддинга (`model="small"`, `num_jitters` повышает точность за счёт повторных проходов).
2. **Сбор фотографий** — рекурсивный обход папки (`collect_photos`); папка `find_results/` исключается, чтобы повторные запуски не искали лицо среди своих же результатов.
3. **Дедупликация** — одинаковые файлы отсекаются по md5-хэшу.
4. **Сканирование** — каждое фото уменьшается до 600px и кодируется; расстояние до опорного лица считается через `face_recognition.face_distance` (евклидова метрика). Если оно меньше `tolerance` — фото попадает в результаты. Сканирование идёт либо в одном процессе, либо в пуле процессов (`ProcessPoolExecutor`, до 4 воркеров) с откатом на последовательный режим при ошибке.
5. **Сохранение** — результаты сортируются по возрастанию distance, пишется `results.txt` и копируются топ-N совпадений в `top_matches/`.

### Как связаны модули

- `findmyphoto.py` и `search_cli.py` импортируют `search_core` и вызывают единственную функцию `find_photos(photos, reference, tolerance, ...)`, получая на выходе dict со статистикой и списком совпадений.
- Прогресс передаётся из ядра наружу через callback `progress_callback(done, total, path)` — CLI обновляет `tqdm`, GUI — прогресс-бар.
- Благодаря единому ядру изменение логики (модель, tolerance, топ-N, форматы) делается в одном месте и сразу работает в обоих интерфейсах.

### Формат совпадения

Каждый результат — dict:

| Поле | Значение |
|------|----------|
| `path` | путь к фотографии |
| `distance` | евклидово расстояние до опорного лица (меньше = точнее) |
| `faces_count` | сколько лиц найдено на фото |
| `face_index` | индекс лучшего лица на фото |

### Ограничения

- Обработка CPU-bound: при отсутствии воркеров (`-w 1`) сканирование однопоточное и занимает несколько минут на 1000+ фото.
- Для скорости используется модель `small` и уменьшение до 600px — на сильно размытых или крошечных лицах точность ниже, чем у полной модели.
- Порог сравнения `tolerance=0.6` эмпирический: ниже — меньше ложных срабатываний, но можно пропустить реальные совпадения.
